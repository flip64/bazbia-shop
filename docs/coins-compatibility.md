# سازگاری بخش سکه با کالاهای عادی

نسخه بازبینی‌شده ۱۸ اکتبر ۲۰۲۶. این نسخه جایگزین بسته قبلی بک‌اند است؛ migration تازه ندارد.

## اصلاح‌های این بازبینی

- محدودیت یک عدد فقط برای واریانت متصل به CoinSpecimen یا CoinPackVariant با sale_mode=unique است.
- کالاهای عادی به ثبت تصاویر اختصاصی، وضعیت انتشار سکه یا ساخت snapshot سکه نیاز ندارند.
- کنترل قفل موجودی، واریانت‌های ثبت‌شده سکه را از واریانت‌های عادی جدا می‌کند.
- تغییر صرف قیمت طبق رفتار فعلی پروژه انجام می‌شود.
- تغییر گروهی variant در SupplierOffer دیگر برای همه کالاها ممنوع نیست؛ مقصدهای CASE که bulk_update تولید می‌کند از SQL محاسبه و فقط قواعد سکه روی مقصد مرتبط اعمال می‌شوند.
- جلوگیری از لغو در processing و آزادکردن زودتر رزرو فقط برای سفارش دارای سکه یا پک، از جمله سفارش ترکیبی است؛ سیاست قبلی لغو سفارش کاملاً عادی باقی می‌ماند.
- ثبت snapshot و ممنوعیت بازنویسی آن فقط برای ردیف‌های مرتبط با سکه/پک است؛ snapshot ردیف عادی {} است و bulk_create عادی مجاز می‌ماند.

دو اصلاح عمومی پرداخت، آگاهانه برای همه کالاها حفظ شده‌اند:
۱. مسیر mock نمی‌تواند پرداخت واقعی زرین‌پال را تأیید کند.
۲. پرداخت موفق پس از لغو سفارش ثبت و requires_review می‌شود، بدون زنده‌کردن سفارش لغوشده و فروش موجودی آزادشده.
بنابراین نمی‌توان گفت هیچ رفتار مشترکی تغییر نکرده است؛ این دو تغییر برای جلوگیری از تأیید اشتباه پرداخت و سفارش‌اند.

## آزمون‌های کالاهای عادی

در coins/test_ordinary_products.py شانزده آزمون مستقل اضافه شده:
- موجودی بیش از یک و save/update/F/bulk_update؛
- پیشنهاد تأمین‌کننده و تغییر گروهی مقدار یا واریانت مقصد؛
- جلوگیری از انتقال گروهی پیشنهاد به واریانت سکه‌ای که آن منبع را مجاز نمی‌داند؛
- bulk_create محصول، پیشنهاد و ردیف سفارش عادی؛
- افزودن به سبد بدون تصاویر یا انتشار مخصوص سکه؛
- خرید داخلی و بازگشت موجودی و لات پس از لغو؛
- خرید از تأمین‌کننده و بازگشت مقدار پیشنهاد؛
- خرید ترکیبی از داخلی و تأمین‌کننده؛
- قیمت تخفیفی، مبلغ اقلام و پرداخت موفق؛
- سیاست قبلی لغو سفارش عادی با پرداخت processing؛
- سبد ترکیبی سکه و کالای عادی و snapshot فقط برای سکه؛
- rollback دسته مختلط بدون تغییر ناقص موجودی کالای عادی.

```bash
python manage.py test coins.test_ordinary_products --settings=coins.test_settings
python manage.py test coins --settings=coins.test_settings
```

۱۰۰ آزمون سکه/API/عملیات و کالاهای عادی روی Django 5.2.18 و SQLite جدا پاس شدند.
check و بررسی نبود migration جدید نیز موفق بود.
این نتیجه تضمین رفتار همه افزونه‌ها و داده‌های سرور نیست. MySQL، کرون تأمین‌کنندگان، باسلام، پیامک، حسابداری و اتصال واقعی زرین‌پال در محیط تولید اجرا نشده‌اند.
پس از ادغام با کد جاری، قبل از فروش واقعی یک سفارش عادی و یک سفارش سکه در محیط آزمون سرور بررسی شوند.
